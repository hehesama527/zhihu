# X Traditional 工作台改造计划

## 目标
- 把当前“长表单 + 控制台堆叠”的 X Traditional 页面，改造成有明确主任务、清晰分流和稳定步骤边界的运营工作台。
- 让用户进入后 5 秒内能判断：当前账户是谁、现在有哪些待处理事项、下一步该去哪个页面。
- 不新增后端接口，所有改造建立在现有 `x-traditional-api` 和现有前端样式体系之上。

## 页面结构
### 1. `/twitter`
- 作为 X 工作流入口页，只承担分流，不承载具体编辑工作。
- 首屏只保留两个主入口：
  - `传统链路工作台`
  - `配置与说明`
- 次级入口保留热点与监控列表，但降级为辅助说明区。

### 2. `/twitter/traditional`
- 作为 Traditional 工作台总览页。
- 固定包含四个区块：
  - 当前账户摘要
  - 待处理任务摘要
  - 系统运行状态
  - 推荐下一步
- 固定提供三个主动作：
  - `新建任务`
  - `从参考账号学习风格`
  - `执行待处理任务`

### 3. `/twitter/traditional/tasks`
- 承载任务创建、任务筛选、任务执行。
- 页面重点是任务工作流，不混入账户定位和学习流程。

### 4. `/twitter/traditional/account`
- 承载账户定位编辑与 Soul 预览。
- 页面重点是确认“这个账号是谁、写给谁、代表性表达是什么”。

### 5. `/twitter/traditional/learning`
- 承载 Note Agent 学习流程。
- 固定按 5 步向导呈现：
  1. 选择目标账户
  2. 配置参考账号
  3. 生成样本与查看采样结果
  4. 审阅学习草稿
  5. 确认写回

## 导航与文案
- X 侧栏标题统一为 `X Traditional 工作台`。
- 侧栏导航统一为：
  - `工作台总览`
  - `任务`
  - `账户定位`
  - `风格学习`
  - `配置中心`
- 术语统一替换：
  - `X Traditional Studio` -> `X 传统链路工作台`
  - `Worker` -> `任务执行器`
  - `跑一轮 Worker` -> `执行待处理任务`
  - `Prompt Center` -> `配置中心`
  - `账户 Soul` -> `账户定位`
  - `Note Agent 账户学习代理` -> `从参考账号学习风格`
  - `写回账户资产` -> `确认并写回`

## 实施原则
- 不新增后端接口，不修改 API 请求/响应结构。
- 保留现有 `.card`、`.stack`、`.button` 等样式体系，不引入 UI 库。
- 静态说明区弱化阴影与交互，主操作区保持清晰对比。
- 优先保证桌面端主路径清晰，同时确保移动端不崩坏、可读可点。

## 交付验收
### 代码检查
- 运行 `npm run typecheck -w @zhihu-mvp/web`

### 浏览器走查
- 打开 `/twitter`，确认入口不再是 disabled 占位页。
- 打开 `/twitter/traditional`，确认首屏只出现总览和推荐动作。
- 打开 `/twitter/traditional/tasks`，确认能切换账户、创建任务、筛选任务、执行任务。
- 打开 `/twitter/traditional/account`，确认能编辑账户定位并看到预览。
- 打开 `/twitter/traditional/learning`，确认 5 步向导顺序明确，生成草稿与写回区分清楚。
- 打开 `/twitter/prompts`，确认已进入“配置中心”命名体系，并能返回 Traditional 工作台总览。

### 人工测试准备标准
- 页面无明显乱码。
- 关键入口都能点击到目标页。
- 主要按钮文案与行为一致。
- 数据加载正常，空状态和错误状态可理解。
- 用户可以按“总览 -> 子页 -> 返回总览”的路径连续操作。
